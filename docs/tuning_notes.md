# tuning_notes —— 第一站正反面算法的调参史 / 证伪账

代码（`inspector_pure.py` 头部分节常量）记录的是**算法最后是什么**；这本记录的是代码装不下的
**「为什么这么选、试过哪些没走通」**——这些结论是真金白银调出来的，重踩一遍代价最大，而它们天然
写不进常量注释（一行常量塞不下一段推翻史）。

> **范围**：只服务**第一站正反面翻边止口**（`inspector_pure.py`，黄金基线 318/352 & 623/623 零逃逸）。
> 第二站缺粒的判据史在 `inspector_missing.py` 头部 docstring、成像侧在 `docs/missing_camera_config.md`，
> **不在这里**。
> **当前生效阈值一律以代码为准**，本文只给「为什么」并指向常量所在行；两者冲突时信代码。
> **安全铁律贯穿全文**：真 NG 判 OK（逃逸）不可接受，过杀可接受——下面每个「为什么这么选」
> 最终都归到这条不对称成本上。

---

## 1. 特征 A：判别力在「环带里有没有同心环边」，不在孔径 / 斜率

- **结论（代码：`FEATURE_A_MODE="hough"` @ `inspector_pure.py:195`）**：特征 A 的物理信号是**锥唇的
  同心暗环**；`hough` 分支（找环带里的同心环边）才有判别力，`contour` 分支基本没有。切 `hough` 是
  **零代价 Pareto**（正面召回不掉、反面误判降）。
- **证伪的弯路**：一开始去量**孔径**和**边缘斜率**——量错了地方，那两个量在正反面上分不开。真正
  分得开正反的信号是锥唇那圈暗环，不是孔的大小或壁的陡峭。
- **领圈闸把 A 补成真闸（代码：`COLLAR_GATE=True` / `COLLAR_DARKFRAC_MIN=0.12` @ `:218,226`，
  2026-09-22 全量 975 张验收锁定）**：`darkfrac` = 领圈带 `[1.00,1.35]r` 里比外侧亮环暗的像素占比。
  加这道闸后 **反面 A 孔级 47%→3.5%、图级 87%→16%**，**正面召回 340 不掉、逃逸 0**。
  0.12 是「正面 340 不掉」这个免费段里最紧的一档。

## 2. 特征 B：`MIN_VALID_MARKS=2` 是唯一最优，不是可调旋钮

- **结论（代码：`MIN_VALID_MARKS=2` @ `:246`，2026-09-21 全量重算）**：单孔要 ≥2 个有效压痕。
  - **`tm=1`（放松）→ 13 个逃逸**：一孔侥幸冒一个误检压痕就放行，直接破零逃逸铁律。
  - **`tm=3/4`（收紧）→ 过杀 100/222**：正面正常件也凑不够，过杀爆炸。
  - **所以 2 是唯一同时零逃逸且过杀可接受的值。** 旧的 64/136/284 三组结论是错算，**已作废**。
- **`MARK_CIRCULARITY_MIN` 在 0.60~0.90 对 `tm=2` 判定毫无影响**（代码：`MARK_CIRCULARITY_MIN=0.75`
  @ `:245`）：软接受路径（`position_ok and shape_ok`）主导，圆度硬阈值很少是决定项。想靠调圆度
  阈值改判定基本无效——别在这上面耗。
- **孔越多越好**：受检孔越多件级判据越稳（`--holes 0` 全孔离线统计比生产 2 孔样本量大 5 倍）。
- **92% 是同轴光的召回天花板**（见 §6）：B 再怎么调也顶不破，那是照明物理限制不是算法。

## 3. 反面定位曾经是坏的（P0），修法是「定位不可信就否决」

- **病根**：反面定位坏在 `fit_circle_robust`（`:579`）**谎报内点数**——**69% 的反面图用的是假节圆**，
  后续 ROI 全错位。这是最隐蔽的 bug：判定看着在跑，其实站在错误的节圆上。
- **修法：CFG5 → CFG7（boundary 锚定）**——正面 **340/352（96.6%），其中 +50 是合法召回不是抖动**、
  **逃逸 0**；反面 `pitch_fit` 命中 **213→330**。
- **落地为闸（代码：`HOLE_PITCH_GATE=True` @ `:268`，`on_pitch` 节圆闸）**：**定位越不可信，闸越要
  否决**——孔心不落在节圆上（`on_pitch=False`）就前置否决该孔。
- **副产物**：修定位时暴露过「NG 全靠特征 B 撑着」（A 那时没判别力），已由 §1 领圈闸解决。

## 4. 件级压痕广度闸 `K=4`：把逃逸门槛从「1 孔侥幸」抬到「4 孔各自侥幸」

- **结论（代码：`PART_MIN_MARKED_HOLES=4` @ `:286`，2026-09-22 锁 K=4）**：判 OK 除「有 1 个孔
  on_pitch&A&压痕≥2」外，再 AND「整件 on_pitch 孔里至少见 1 痕的孔数 ≥4」。正面 **340→318（90.3%）**，
  **逃逸仍 0**。
- **这不是新物理维度，是把 B 硬化**：单孔侥幸糊弄过去的概率不低，但要 4 个孔**各自**都侥幸，概率被
  指数压下去。牺牲的是过杀（340→318），换的是逃逸门槛抬高——符合成本不对称。
- **⚠ 必须记住的操作事实（代码里绝对没有）**：工件在**振动盘**上，拒件**回流重拍**。所以**过杀很便宜**
  （件会再转回来重拍），但**一个真 NG 每回流一趟就是一次逃逸抽奖**——过杀方向可以放心收紧，逃逸
  方向一次都不能松。这条是「为什么宁可过杀」的现场根据。

## 5. 残料 / 底板假 OK：`MIN_HOLE_COUNT` 2→4 + 拒绝 mask_centroid

- **结论（代码：`MIN_HOLE_COUNT=4` @ `:150`，2026-09-20 由 2 提到 4）**：有效圆孔 <4 直接 NG，再加
  拒绝 `mask_centroid` 定位。修掉了**残料 / 底板被判 OK**的假 OK，**零召回损失**。
- **JPEG 会翻判**：JPEG 压缩伪影足以改变压痕圆度 / 边缘 → 翻转判定。所以 **RAW 与无叠加结果图一律
  存 PNG**，不存 JPEG。（存图策略见 README「目录与日志」。）

## 6. 成像天花板：85% 的 `hough_miss` 是照明问题，软件补不回

- **根因**：85% 的失败拐角是 `hough_miss`（Hough 一个圆都没找到）——**同轴光垂直照浅凹坑没有影**，
  压痕根本没形成足够边缘。这是照明物理，**软件补不回来**。
- **出路是硬件**：要顶破 92% 召回天花板，得**加一路低角度外部光**打出压痕的影，不是调算法。
  `dbg_report` 的 `hough_miss` 诊断格画 Canny 边缘，就是用来区分「根本没边（照明）」与「有边不成圆
  （p2 偏高）」——现场几乎全落在前者。

## 7. 性能：那些毫秒是 Python 循环，向量化即 25x 无损 → 不用 C++

- **`refine_hole` 逐角度找孔壁循环已 numpy 向量化**（argmax 首个跨越 + float64）：**判定 100% 等价**
  （全量 `--sweep` 自检 318/352 & 623/623 一致、4551 拐角逐一保真），`refine` 从 ~74ms/帧 降到生产态
  **16.74ms**，`inspect_total` **41.94ms**。
- **`fit_circle_ransac` 的 3 点枚举循环已向量化**（闭式外接圆）：**26~33x**，判定过全量 `--sweep` 一致，
  根治了 `locate` 定位工件 **max=352ms 的尾巴**（该尾巴随候选点数 n 暴涨）。
- **结论**：拖时间的是 **Python 循环**，不是能沉进 C++ 的数值计算。向量化拿到 25x 且判定无损，
  **所以没必要上 C++**（省掉一整条编译 / ABI / 跨平台的账）。
- **已否决的弯路**：tier2 外圆 Hough 那块做**下采样不安全**（会改选到不同的圆），否决。
